# 深圳市政府数据开放平台：接入前要过的三关

> 结论先行：**接口是活的，形状清楚，只差一个有效 `appKey`。**
> 而 `appKey` 不是「注册就有」，是「提交一个应用成果才有」——四种成果类型里
> 有一种是 **web 应用**，我们已经有站点，可以申。
>
> 顺带一个意外收获：**目录本身不需要账号就能枚举**，2,791 个数据接口的元数据
> 全部可读。所以「标着每年更新、其实两年没动」这类结论，今天就能算。

本文只记录**验证过的东西**和**还没验证的东西**，两者分开写。2026-11-21 用
`sz-probe.sh` 复核过第 1、2、3 节与全部匿名统计；带日期的数字是当时的记录，
可现场重算的部分见第六节。

## 一、不需要账号就能确认的事

| 动作 | 请求 | 实测返回 |
|---|---|---|
| 列接口目录 | `POST /data/api/findPageByParams` | 2,791 条（市级 1,747 + 区级 1,044），`pageSize=2000` 两页取全 |
| 调数据，不带 key | `GET /api/29200_00000001/1/service.xhtml?page=1&rows=2` | `{"errorCode":"10009","message":"appKey不能为空"}` |
| 调数据，带错 key | 同上 + `appKey=0…0` | `{"errorCode":"10001","message":"未经许可的证书"}` |

这两条错误码比「页面打不开」有用得多：**接口是通的，鉴权层在正常工作，缺的只是授权。**
拿它当探针，接平台前先把「到底是接口坏了还是没权限」区分开。

目录每一条自带这些字段（都匿名可读）：

| 字段 | 含义 | 我们拿它算什么 |
|---|---|---|
| `resTitle` / `officeName` | 名称 / 数源单位 | 榜单条目与部门榜 |
| `openLevelName` | 无条件 / 有条件开放 | 2,563 个无条件，228 个有条件 |
| `openFieldCount` | 声明字段数 | 字段数口径（只有数量，没有名字） |
| `recordTotal` | 数据量 | 与 `openFieldCount` 一起做「像不像真的」 |
| `updateCycle` / `dataUpdateTime` | 声称周期 / 实际入库时间 | **停更判定，这条今天就能出结论** |

按 assay 自己的周期阈值粗算：**2,791 条里 163 条的声称周期已经过期**，截至
2026-11-21 最久的一条 **2,666 天**没更新（「统计月报-国民经济核算」，声称按月，
`dataUpdateTime` 停在 2019-08-04）。这批不需要任何授权。

口径要说透：深圳的 `updateCycle` 写的是中文「按日 / 按月 / 按年」，而
`crates/core/src/aggregate.rs` 的 `BAD_CYCLE` 表用数字编码 `1 / 30 / 365`
（另认「每年」），**assay 本身不直接认中文**。要人工映射成 7 / 45 / 400 天才能套。
早期笔记里的「最久 726 天」是同一口径算错：滞后只会随时间增长，三天不可能差
1,940 天；2026-11-21 用探针第 1b 节复核为 2,666 天。

口径还要交代清楚：深圳实际有八种周期说法，assay 的阈值表只覆盖按日 / 按月 / 按年。
**2,212 条暂时判不了**：有数据更新时 1,830 / 存档 326 / 半年 35 / 按季 14 / 按周 7。
要新增规则才能算——不能把「判不了」混进「没问题」。

**拿不到的是什么**：样例行。`openFieldCount` 只给数量不给字段名，字段对不上、
空值率、整列为空这些「货不对板」的核心判定，全都要真实数据行。所以榜单要成立，
`appKey` 还是绕不过去。

## 二、拿 appKey 的三步（人来做，约 10 分钟 + 等审核）

依据是平台官方文档 [《API 调用操作指南》](https://opendata.sz.gov.cn/downloadFiles/open-file/Api%E6%8E%A5%E5%8F%A3%E8%B0%83%E7%94%A8%E6%93%8D%E4%BD%9C%E6%8C%87%E5%8D%97.pdf)，
不是猜的。

### 1. 注册

两个入口，字段数不一样，按实际情况选：

- 个人注册（`/maintenance/authentication/toRegister?type=person`）：登录账号、密码、
  真实姓名、手机号 + 短信验证码、邮箱（选填）、图形验证码，勾选《授权协议》。
  **不需要身份证号**，但手机号要能收码。
- 机构注册（`?type=company`）：用户名、机构类型（企业法人 / 国家机关法人 /
  事业单位法人 / 社会团体法人）、机构全称、**统一社会信用代码**、密码。

### 2. 提交应用成果，拿 key

路径：首页【应用】→【开发者中心】→【应用成果提交】。

官方明确给了四种类型：移动 app、微信小程序、**web 应用**、研究报告。填应用名、
开发者类型、简介，提交后在【个人中心】→【应用成果】查看对应的 `appKey`。

我们选 **web 应用**——理由很实际：站点已经在线（GitHub Pages），有真实地址可填，
不需要为拿 key 先造一个移动端。

### 3. 订阅接口

`appKey` 只是身份，不是权限。要调某个接口，得先进那个接口页面点【订阅】，
选中刚提交的应用：

- 无条件开放的接口（2,563 个）：订阅即可调用；
- 有条件开放的接口（228 个）：要数源单位审核，等。

官方还提供【个人中心】→【接口测试】，可以不写代码直接试参数。

## 三、接入地址的形态（两个坑）

调用地址是：

```text
https://opendata.sz.gov.cn/api/{resId}/1/service.xhtml?page=1&rows=10000&appKey={key}
```

参数：`page`（从 1 开始）、`rows`（每次最多 10,000）、可选 `startDate` / `endDate`
（`yyyymmdd`，按**入库日期**筛，不是业务日期）。

**坑一：`resId` 里的斜杠要换成下划线。** 目录返回的是 `29200/00000001`，
调用地址得写 `29200_00000001`。写成斜杠不会报错——返回 HTTP 200 加一个平台首页
HTML。这种「200 + 一坨 HTML」比 404 难查得多，脚本里专门标了。

**坑二：返回字段名是拼音缩写，不是中文。** 例如 `NF`=年份、`NMCZRKS`=年末常住人口数。
而平台「声明字段」是中文描述。按 `docs/DECISIONS.md` D5 的分类，这两者天然
「字段集合不一致」——**所以深圳榜不能直接沿用浙江的判定逻辑**，得先定口径：
是只比字段数，还是维护一份「缩写 ↔ 中文」映射表。这是接第二平台真正的工作量，
不是写 transport。

## 四、拿到 key 之后，代码要改哪里

按 D25 已经把形状从边界上清干净了，所以只需要：

1. 新增 `SzClient`，`impl CatalogSource`：目录走 `findPageByParams`，映射成
   `DatasetMeta { columns, has_preview, description_len }` + `Vec<Vec<String>>`；
2. `audit --source sz` 的参数化（现在是写死浙江）；
3. **先定第三节坑二的口径**，否则 `schemaMismatch` 会把 2,791 条全标成问题——
   那不是发现，那是没对齐。

## 五、还没验证的（别当结论）

- 应用成果的审核时长，以及 web 应用是否需要核验站点归属（备案？）；
- 调用配额与 QPS：官方文档只写了每页上限 10,000 条，**没写频次限制**；
- 228 个有条件开放接口的审核通过率；
- 目录接口（`findPageByParams`）是否长期匿名可用——它现在开着，但平台随时可以关。

## 六、一条命令复核本文数字

```bash
./scripts/sz-probe.sh              # 只验不需要 key 的部分
./scripts/sz-probe.sh <appKey>     # 拿到 key 后顺带验一次真实调用（key 不出现在输出里）
```

只读、不写本地文件、不打印密钥。第 1 节能通说明目录开放；第 1b 节当场重算
开放级别、周期覆盖率与过期数（早期笔记里这几个数只能人工复核，现已补进脚本）；
第 2、3 节的错误码说明接口活着。

第 1b 节的数字是**运行当天**算的，最久滞后会随时间增长，别和 11-18 的旧笔记对不上
就以为是数据漂了。真要判断是否漂移，比的是同一天的两次采样。
