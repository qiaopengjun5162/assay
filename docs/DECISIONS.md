## D30 阈值与判定收成一张表，并把这张表发布出去

**背景**：抽检查项时发现阈值散在四个文件里：`desc_len < 10` 写在 `scoring`、
`aggregate`（两处）和前端（`app.rs` 的「有说明 / 说明过短」）；`STOPPED_CYCLES`
写在五处；`> 0.3`（空值率）、`> 90`、`> 365`（滞后天数）各一处。改一处忘一处
不会编译失败，只会让首页的数字和详情页的措辞互相打脸。

顺带查出两处**已经存在**的口径冲突，都靠「把命中数跟 summary 逐项对齐」才发现：

| 概念 | 一处定义 | 另一处定义 | 真值 |
|---|---|---|---|
| 结构对不上 | `aggregate` 手写三选一 | `SchemaKind::is_mismatch()` 手写两选一 | 1,284 vs 1,256，差 28（「仅命名不一致」） |
| 有预览 | `summary.withPreview` 数「行数 > 0」 | 检查项 `no-preview` 数 `hasPreview == 0` | 差 51——平台给了表头但零数据行 |

`is_mismatch()` 没有任何调用者，但谁先拿去用谁就把统计搞错，且不会有任何报错。

**决定**：

1. 新建 `crates/core/src/checks.rs`：`id / 人话 / 维度 / 权重 / 阈值 / 规则`
   只在这里出现一次。`scoring`、`aggregate`、`export`、前端全部从这里取。
2. 「结构对不上」统一为 `checks::schema_mismatch()`（三选一并集，与
   `summary.schemaMismatch` 同口径），删掉口径不同的 `is_mismatch()`。
3. 「有预览」拆成两条独立检查：`no-preview`（平台不给）与
   `preview-header-only`（给了表头没给行）。两个概念两个名字，不再共用一个数。
4. 这张表随 `export` 发布进 `data.json` 的 `checks` 字段（含全量命中数），
   站点在榜下面原样印出来；`assay checks [--json]` 也能打。**尺子要可见**——
   读者问「凭什么说它有问题、门槛多少」，不该需要翻 Rust 源码。
5. 权重为 0 的项（`empty-rate-high`、`overdue-claim`、`preview-header-only`）
   明写 0 并且注明原因：不参与排序就说清楚，不让人猜。

**为什么不做 `checks.yaml`**：ROADMAP 原话是「让数据提供方自己写检查」。真做成
配置驱动就得写一个表达式求值器，随之而来的是拼错字段名静默不命中、未知算子、
配置与代码版本错位——全在确定性路径上。现在这张表是数据、`fires()` 只有一处实现，
不存在两条执行路径；等真有外部作者了再谈 YAML，那时也知道该支持哪些算子。

**代价**：新增一条检查要动一个 Rust 文件（而不是一个配置文件）。这是刻意的——
每条检查都得有人想清楚「算不算得出来、算不出来要不要标不评价」。

## D29 复核命令必须用绝对 URL，且要能一键复制

**背景**：ROADMAP 把「浏览器内独立复核」列为第一优先，判据是评委不装东西就能验。
页面早已有 `VerifyButton`（浏览器内重算 + 逐字符对照），但同一屏印出的 `shasum`
命令用的是 `data.json` 里的相对路径 `evidence/...`。实测：干净环境下
`curl -O evidence/foo/detail.json` 直接 `Could not resolve host: evidence`；
开着代理时更隐蔽——代理会返回一张 108 字节的错误页，退出码还是 0，评委以为验过了。
也就是说「一键复核」的两条路，一条（浏览器按钮）通，另一条（命令）是坏的。

**决定**：

1. 命令里的两个文件地址在渲染时用 `location.origin() + location.pathname()` 补成
   绝对 URL。纯字符串逻辑抽到 `crates/web/src/verify.rs`，不依赖 Leptos / web-sys，
   因此能在 native 下单测——命令少一个字符评委就验不了，这种代码必须有测试。
2. 加「复制命令」按钮（`navigator.clipboard.write_text`）。剪贴板只在安全上下文
   可用，失败时如实提示手动选中，不假装成功。
3. web 单测进 `just test` 与 CI rust job。此前 web crate 不在任何测试门禁里，
   纯函数改动无人拦。

**为什么不让后端生成命令**：命令依赖「评委当前所在站点」的地址，只有浏览器知道；
后端生成会把 `localhost` 或 Pages 子路径写死，反而更错。

## D28 深圳不是「注册就给 key」，而且目录本来就不用 key

**背景**：D25 那张表里深圳写的是「需实名注册领 APPKEY，属授权问题」。这句话有两处不准，
2026-11-18 实测纠正——两处都朝「比想的容易」的方向错。

**纠正一：目录不需要账号。** `POST /data/api/findPageByParams` 直接返回 2,791 条
数据接口（市级 1,747 / 区级 1,044），每条都带 `openFieldCount`、`recordTotal`、
`updateCycle`、`dataUpdateTime`。也就是说「标着每年更新、其实两年没动」这类结论
**今天就能算**：按 assay 的周期阈值粗算，163 / 2,791 已过期，最久 726 天。

**纠正二：key 不是注册的产物，是「应用成果」的产物。** 官方《API 调用操作指南》
写的是四类成果——移动 app / 微信小程序 / web 应用 / 研究报告——提交后在
【个人中心】→【应用成果】取 `appKey`；而且拿到 key 还要在**每个接口页点订阅**。
路径是「提交一个 web 应用 + 逐个订阅」，不是「实名认证后自动发 key」。

**为什么纠正值得记**：「等实名审批」听起来像一道行政门槛，很容易被排成
「两个月的外部依赖」然后束之高阁；真实路径需要人操作，但一周内能推进，而且我们
本来就有站点可当 web 应用提交。**把可控的事误判成不可控，是最贵的一种悲观。**

**顺便留下两个坑（接的时候会用上）**：

| 坑 | 表现 | 正确做法 |
|---|---|---|
| `resId` 形态 | 目录给 `29200/00000001`，直接拼进 URL 得到 **HTTP 200 + 平台首页 HTML**，不报错 | 调用地址用下划线 `29200_00000001` |
| 字段名语言 | 返回 `NF` / `NMCZRKS` 这类拼音缩写，平台「声明字段」是中文 | 先定口径：只比字段数，还是维护缩写映射 |

**边界**：本次**没有**写抓取管线，只加了 `scripts/sz-probe.sh`（只读、不落盘、
不打印密钥）和一页勘察记录 `docs/audit/SHENZHEN.md`。接不接、按什么口径接，
要等口径问题有答案——否则 `schemaMismatch` 会把 2,791 条全标成问题，那不是发现，
是没对齐。

## D27 门禁不进 CI，等于没有门禁

**背景**：`just typos` 从加进 Justfile 那天起就是红的，谁也不知道，因为 CI 不跑它。
两条原因：`flate2` 被拆词成 `flate`（被判成 `flat` 的拼写错误），
`pack.rs` 测试里两个变量叫 `ba` / `bb`（被判成 `by` 的笔误）。

**为什么这比「有个检查没跑通」严重**：Justfile 写着这条命令，读代码的人会以为
「拼写这块有人管」。挂着不跑的门禁比不挂更糟——它生产的是虚假的安心。

**决定**：

1. `_typos.toml` 里把 `flate` 声明为合法词（去掉误报），变量改成 `bytes_a` / `bytes_b`
   （改名而不是加忽略：`ba` 这个名字本身就没有信息量）。
2. `just check` 收进 `typos`；没装工具时**报错并给出安装命令**，不静默跳过。
3. CI 的 docs job 加一步 `crate-ci/typos@v1`。

**为什么不忽略整类文件**：忽略 `docs/**` 能让它立刻变绿，但那样查的就只剩代码注释，
而这仓库里字最多的地方恰恰是文档。

## D26 页头的日期不再写死：跑批清单是唯一诚实的来源

**背景**：`export` 里有一行 `const SNAPSHOT_DATE = "2026-11-14"`，注释写着
「重跑审计时跟着改」。事实是没人会记得改。于是首页写「抓取于 2026-11-14」，
而同页 500 份证据每份都写着 `fetchedAt: 2026-11-18`。

**实测（文件时间，不是记忆）**：`items.jsonl` / `summary.json` 写于 11-14 17:49–17:51，
`evidence.json` 写于 11-18 16:25。两个日期都是真的，只是属于两批不同的动作：
**体检**与**证据复核**。页面只说了其中一个，还说的是常量的那个。

**决定**：

1. `audit` 在新一轮开跑时写 `run.json`（`capturedAt` 等）。续跑沿用第一次的日期，
   否则同一批数据会显示成两天。
2. `export` 取日期按三档：`--snapshot-date` 显式给 → `run.json` → 证据里出现最多的
   抓取日期（众数，不是最大值：跑批跨零点时取最大值会把整批推后一天）。
3. **三档都拿不到就报错**，不猜。以前那个常量就是「猜」的一种：它不报错，只是安静地变旧。
4. 来源本身也落盘（`generatedAtFrom`: `run.json` / `evidence` / `explicit`）。
   同样的日期，来自清单和来自「记得传参数」是两件事，读产物的人有权知道是哪种。
5. 页头措辞从「抓取于」改成「**体检于**」：这个日期说的是体检批次，
   证据卡的「抓取时间」说的是复核批次。两个名字，两个日期，不再互相拆台。

**这次冻结的产物怎么处理**：`web/data.json` 用 `--snapshot-date 2026-11-14` 重新导出，
产物里标 `explicit`——因为这次跑批发生在 `run.json` 机制之前，没有清单可读。
除此之外与提交版逐字段相同（500 行、`summary`、`total` 全等），所以这不是「改数据」，
是给同一个日期补上出处。

**代价**：`export` 多了一个可能失败的分支；`audit` 多写一个小文件。

## D25 第二平台先不接：挡路的不是代码，是数据授权

**背景**：`docs/ARCHITECTURE.md` 一直写着「换平台只实现 `CatalogSource`」。这句话当时
**不成立**：`audit` 里还在读 `detail["result"]["columnList"]`、`hasPreviewData`、
`dopSourceInfo.description`，样例读 `result.data`——都是浙江的形状。trait 只抽了方法名，
没抽数据形状。真要接第二家，得同时改 `audit`、`proof` 和测试。

**决定一（本次做掉）：把形状从边界上清掉。**
`CatalogSource` 现在只交归一化数据：`DatasetMeta { columns, has_preview, description_len }`
和 `Vec<Vec<String>>` 表格（第一行表头）。浙江的解析收进 `meta_from_zj` /
`preview_rows`，只被 `impl CatalogSource for Client` 调用。新增 `rows_from_raw`，
让「解析已存证的快照」也归适配器管——证明必须针对快照（D20），但怎么读快照是平台的私事。
`tests/pipeline.rs` 的 `FixtureSource` 改成只返回字段名和行，一个字节的平台 JSON 都没有；
它跑通就是这条抽象成立的证据。

**决定二（本次不做，附实测）：第二家暂时接不了。**

| 平台 | 实测 | 结论 |
|---|---|---|
| 上海 data.sh.gov.cn | `/`、`/api/`、`/api/search` 全部 **HTTP 412**，返回带 `$_ts` 的混淆脚本 | 瑞数类动态防护，整站挡，连接口路径都进不去 |
| 江苏 data.jiangsu.gov.cn | 主页 403，换 UA 后 504 | 不稳定，不可依赖 |
| 深圳 opendata.sz.gov.cn | 页面 200；`/data/api/{selectDataApiByResId,getPreviewApiItem,getPreviewApi}` 存在，裸调返回空 | 需实名注册领 APPKEY，属授权问题（**2026-11-18 更正，见 D28**：目录匿名可枚举，key 要提交应用成果并逐个订阅）|
| 山东 data.sd.gov.cn | `/portal/api/` 是接口目录页，服务端渲染 HTML；接口详情页也是 HTML | 要解析页面 + 逐个申请 |
| 北京 data.beijing.gov.cn | 搜索是 `/cms/web/search/index.jsp`，服务端渲染 HTML | 同上 |
| 成都 / 广州 | 连接超时 | 不可达 |

**为什么这值得记一笔**：把「接第二个平台」当成编码任务排进队列，是最容易自我欺骗的一种
排期——代码两天能写完，数据权限两个月都未必下来。真正的瓶颈是「拿到可机器读取的目录 +
字段定义 + 样例」，而多数省级平台要么上动态防护、要么要求实名申请接口密钥。
所以队列里这一项应当被标成**外部依赖**，而不是待办。

**下一步要接谁**：深圳。它的目录与预览接口形态最接近浙江（POST + JSON + 表头/行），
只差一个 APPKEY；注册免费、需实名。拿到 key 之后要写的只是 `SzClient` 一个 impl 加
一次 `--source sz` 的参数化。

**边界**：本次没有改动任何抓取行为。小样本回归（12 条真实记录 × 12 个字段）与既有产物
逐字段一致，证明重构对现值零影响。

## D24 模型端点、模型名、代理都可配，配置对不对一条命令验

**背景**：`call_model` 把 `https://api.deepseek.com/anthropic/v1/messages` 写死在函数里，
读 key 的逻辑也只认配置文件里含 `api.deepseek.com` 的那几行。2026-11 本机渠道换成
`https://platform.yeta.ai/v1` 之后，`explain` 报的是「找不到 LLM key」——**key 一直好好的，
是读法只认老地址**。这类报错最坏的地方在于它指错了方向：人会去翻 key，实际该改的是端点。

**决定**：端点、模型名、key、代理四件事都可配，解析顺序是
环境变量 → 本机配置 → 兜底值，三段分别独立取（可以只换模型、继续用文件里的 key）。

| 变量 | 作用 |
|---|---|
| `ASSAY_LLM_KEY` | key |
| `ASSAY_LLM_BASE` | 端点 |
| `ASSAY_LLM_MODEL` | 模型名 |
| `ASSAY_LLM_PROXY` | 代理 |

**协议按地址判断**：基址含 `/anthropic` 走 messages（`x-api-key` 头、`system` 在顶层），
其余走 OpenAI 兼容（`Bearer` 头、`system` 作为第一条 message）。渠道换了协议变了，
改环境变量即可，不用重新编译。

**不读 `HTTPS_PROXY`**：本机代理端口经常漂（沙盒里那个 50218 就是个不通的），
误读一个死代理比不读更难查。代理只在显式给 `ASSAY_LLM_PROXY` 时启用。

**附带的 `--probe`**：`explain` 跑 100 条要几分钟，配置错要等几分钟才知道，失败信息
还往往只有一句 HTTP 401。`assay explain --probe` 只发一次请求，打印端点、模型、协议、
脱敏后的 key 与来源、代理、往返耗时。自检路径和生产路径是同一个函数，不会「自检过了
跑批挂」。

**为什么不用 YAML 库**：只需要读一个 `model:` 块，为它引 serde_yaml 并在 RUSTSEC 上
多养一个依赖不值得。读法是「全文第一个 `api_key:` + 它所在 `model:` 块里的
`default`/`base_url`」，读不到就返回 None 让调用方兜底，不 panic。

**验证**：9 条单测钉住解析与请求形状（块格式 / 扁平格式 / 有无 `/v1` / 尾斜杠 /
两种 body / 两种响应 / 脱敏）；本机实测 `--probe` 1.9s 拿到回复。

## D23 可验覆盖从 100 扩到 500：证据不是瓶颈，可证的才不是全部

**背景**：榜单导出 500 条，但只有前 100 名有证据包和 Lean 证明。用户点开第 200 名，
页面写着「字段对不上」，却拿不出任何可以自己复核的东西——「每条结论都能自己验」
偏偏在最需要验的地方断了。100 / 24,322 = 0.4%，看着像只挑了几条做样子。

**实测**（2026-11-18，同一份 11-14 的 `items.jsonl` 上重跑）：

| 规模 | 证据 | 定理 | 可证数据集 | 体积 |
|---|---|---|---|---|
| 100（旧）| 100 份 | 2,355 条 | 100 | 3.2 MB |
| 500（新）| 500 份 | 4,970 条 | **391** | 14 MB |

抓 500 份证据 46 秒，生成并编译 4,970 条定理 + `lean` 校验 20 秒。体积不是问题。

**决定**：证据与报告给满 500 条（导出上限就是 500），证明给到能证的全部 391 个。

**为什么不是 500 个证明**：剩下 109 个数据集，平台返回的 preview 只有表头、没有数据行，
`body.is_empty()` 直接跳过——没有一行数据就没有可证的命题。这不是省事，是数据本身
没有东西可证。页面把这句写出来，比硬凑 500 个数字更可信。

**为什么证据扩了、解读没扩**：解读要调模型，500 条约半小时且消耗额度；而解读是最弱的
一环（模型写人话），证据和证明才是「可验」的实体。先扩实体，解读保持 100 条。
**遗留**：`explain` 的 endpoint 还硬编码 `api.deepseek.com`，本机 key 已不在官方渠道，
重跑解读前得先把它做成可配置 → 已由 **D24** 解决，解读随后扩到 500 条。

**时点一致性**：证据是 11-18 重抓的。逐字节比对 11-14 的 200 个文件，字节数完全相同、
内容只差 `visitsCount` 一个字节——那是平台访问计数器，每抓一次 +1。所以榜单统计（11-14）
与基于快照的证明计数仍然一致；也正因为响应里带这个计数器，「原始响应必须落盘」才不是洁癖。

**边界**：500 是 2.1%，不是全量。全量存证约 3.2MB × 243 ≈ 780MB，不该进 git，
这也是 D20「证据静态、查询走后端」的另一个理由。

## D22 审计包用 tar.gz，且必须可重现

**背景**：`SUBMISSION.md` 第一优先是「验的人不需要装我们的东西」，但证据一直是散在
`out-full/evidence/` 里的 200 个文件。没有「一个可以交出去的物」，这句话就只是口号。
**决定**：`assay pack` 打 `.tar.gz`，包内自带 `VERIFY.md` + 标准 `shasum` 格式的
`MANIFEST.sha256`。实测 100 条证据：3.6MB → **0.4MB**，206 条校验全部 OK。
**为什么 tar.gz 而不是 zip**：`tar` + `flate2` 的依赖树比 `zip` crate 小，且 flate2
默认走 miniz_oxide（纯 Rust，无 C 依赖——这一点在多平台打包时不添麻烦）。
macOS/Linux 双击可解，Windows 10+ 也原生支持。
**为什么 mtime/uid/gid 全固定 0**：否则同样输入打两次字节都不同，「包的哈希」就不能
当批次指纹用。固定之后实测两次都是 `c6f4c23b…`。这条同时让「不入库」变得无害——
重打一遍就能得到逐字节相同的文件。
**为什么保留两级哈希**：单文件哈希只证明「文件没被改」，证明不了「同一条数据的
detail 与 preview 来自同一次抓取」。后者要靠组合指纹
`H(detail ‖ "\n--split--\n" ‖ preview)`，与 `evidence.json` 同口径、原样搬运不重算。
**边界**：包里的证据是**样例级**（受 `just evidence N` 限制），指标来自目录全量元数据。
`MANIFEST.json` 的 `scope` 字段与 `VERIFY.md` 都写死了这一点，不允许把样例说成全量。

## D21 灌库走 CLI 一次传 JSON，不开 HTTP 写接口

**背景**：D20 建了库，但没人往里写——PR #8 只能用临时 SQL seed 验证端点，那能测不能运维。
**决定**：加 `assay-api ingest` 子命令，把一次跑批的产物灌进库；**不开** `POST /v1/ingest`。
**为什么不开 HTTP 写接口**：

1. 「谁能写库」只需要一个人或一个 CI job，「谁能查询」才需要一个服务。把两者塞进同一个
   带鉴权的 HTTP 面，等于为了让一个人写库而给整个网络开一个口。
2. 一旦有 HTTP 写接口，就必须回答「写进来的东西算不算证据」。算，就要先设计签名与吊销——
   那是比 D20 更大的一步，不该顺手做掉。
3. CLI 能在 CI 里跑，不需要服务在线。这条保住了「服务挂了不影响跑批」这个性质。

**为什么一次传整批 JSON**：2.4 万条 × 2 张表 = 4.8 万次往返，本地就要几十秒，跨网络没法看。
`jsonb_to_recordset` 让一条 SQL 处理整批，实测 24,322 条 **3.4 秒**（含读 46MB catalog 快照）。
**为什么不用数组绑定**：`jsonb_to_recordset` 的列名可以直接写成 JSON 键名（`"lagDays"` 加引号），
Rust 侧不用把 camelCase 再映射一遍。少一层映射就少一处会漂移的地方；而且 JSON 天然表达 null，
不用纠结 `Vec<Option<T>>` 的数组编码。
**为什么 CTE 里 upsert dataset 再 join 回 observation**：否则要在 Rust 侧维护 `ext_id → 自增 id`
的字典，2.4 万个键，还要处理并发插入。
**为什么 Rust 侧先去重**：`ON CONFLICT DO UPDATE` 在**同一条命令**里碰到同一行两次会直接报
`cannot affect row a second time`——一条脏数据能让 2 万条全灌不进去。真实数据目前 0 重复，
但平台是公共接口，必须在入口挡住并计数。

## D20 证据保持静态，查询另起后端：D1 的部分修订

**背景**：D1 当初决定「不做后端，静态 JSON + 静态页」，理由是零运维、现场断网
也能演、拿到证据包双击就能验。这三条在「证明结论可复核」阶段是对的，也确实是
卖点。但项目现在要做的是「长期体检」——周度巡检已经把时间维度带进来了（D19）。
**触发信号不是「项目变大了」这种模糊说法，而是一具体数字**：全量 24,322 条下，
`index.json` 7.3MB、详情分片 12MB。每周存一份全量是 19MB，只存索引也要 7.3MB，
一年 380MB 进 git。**静态托管装不下时间序列。**

另外静态方案还有一个结构性缺陷：任意维度组合查询（部门 × 时间 × 指标 × 阈值）
要么预生成所有组合——笛卡尔积爆炸，要么让浏览器把全量拉下来自己算。

**决定**：拆成两半，不是二选一。

| 东西 | 放哪 | 为什么 |
|---|---|---|
| 证据本体（原始响应 / SHA-256 / Lean 证明） | **静态、不可变、可离线** | 依赖服务在线才能验，不叫可验 |
| 索引与编排（哪次体检、每条多少分、随时间怎么变） | **Postgres** | 时间序列与组合查询是数据库的本职 |

新增 `crates/api`：axum 0.8 + sqlx 0.8 + Postgres，四个只读端点。

**边界**（刻意做窄）：不做写接口、不做账号体系、不做任务队列、不把证据存进库。
理由：写接口一开放就要回答「写进来的东西算不算证据」，而这需要先设计签名与吊销，
现在没有那个需求。

**代价**：多一个服务要运维。缓解三条——单实例无状态、启动自动跑 migrations、
可随时清库重建（因为证据不在库里，重建只丢索引，不丢证据）。

**为什么不做 SSR**：SSR 解决的是「首屏 HTML 谁拼」，后端解决的是「状态与查询放哪」。
前者要静态（离线可验），后者要服务。两件事不冲突，但 SSR 会把「双击 index.html
就能验证据」这条卖掉，收益（SEO）对一个榜单工具站很小。

**已知未做**：任务提交（`POST /v1/runs`）、审计包签发与代验、账号。
这三个是产品化的下一步，不是这次的范围。

## D19 漂移判定做成 Rust 子命令，退出码分三档

**背景**：项目原本是「一次性体检」——跑完出报告就结束。数据平台每天都在变，
一次体检的结论三个月后就不可信了。要做周度巡检，第一反应是在 workflow 里
用 `shell + jq` diff 两份 `summary.json`，零代码改动。
**放弃的理由**：阈值逻辑一旦游离在门禁之外，以后改 `summary.json` 字段必然和 core 分叉；
而且它无法单测——「这个阈值到底该不该触发」只能等下周跑出来看。
**决定**：判定逻辑落 `crates/core/src/drift.rs` 纯函数（不碰 IO），`cli` 加 `assay drift` 子命令，
阈值与字段跟 `summary.json` 同源。11 个单测进 `just check`。
**退出码分三档，而不是「漂移 / 没漂移」两档**：

| 码 | 结论 | 处置 |
|---|---|---|
| 0 | 正常 | 基线不动，job 绿 |
| 1 | 漂移 | 交基线 + 报告，开 PR 让人确认「是否接受为新常态」 |
| 2 | 跑批不可信 | 抓取成功率骤降 / 目录条目骤减，**基线不动**，job 直接红 |

**为什么必须分成三档**：漂移和不可信的处置**完全相反**。漂移代表「数据变了，要不要接受」，
该交给人判断；不可信代表「这一轮根本不该拿来比」，如果也走开 PR，就等于把脏数据写进对照系，
之后所有周的漂移判断全部失真。合并成一档，迟早会把一次网络抖动变成一次基线污染。
**基线只在漂移 PR 合并时前进**，代表「上次人工确认过的常态」。这样渐进漂移会一周周累积、
越过阈值才报；如果每周跟着数据走，慢慢烂掉的指标永远报不出来。
**代价**：多约 600 行代码 + 11 个单测；每周 Actions 跑 12 分钟全量。
**为什么值**：阈值可单测、可 review、改字段不会分叉；三档退出码让「脏数据不入基线」变成机制而不是纪律。
**边界**：阈值是经验值（schemaMismatch +2pp、stoppedUpdate +2pp、lagMedianDays +14 天、
emptyRateMedian +0.05），要跑 4 周实测校准。它只告警「该看了」，不判断「为什么变」。

## D18 证据哈希做成双向：能生成，就必须能复核

**背景**：哈希一直在，但只有生成方向。想验一份证据得自己拼 `cat detail.json` + 分隔符 + `cat preview.json`
再喂给 `shasum`，拼错了还不知道错在哪。评委或买方拿到审计包，实际没法验。
**决定**：加 `assay verify-evidence <索引> <目录>`，用与 `capture_top` 完全相同的字节顺序重算并比对，
任何一份不符退出码 1。进 `just check` 与 CI。网站详情页把等价的 `shasum -a 256` 命令直接印在证据面板上。
**代价**：每次 `just check` 多 0.6 秒（100 份）。
**为什么值**：哈希如果只有写没有读，「可复核」就只是一句话。实测：改一个字节 → 退出码 1、报告哪一条不符；
还原 → 退出码 0、100/100 一致。
**边界**：验的是「文件和索引对得上」，不是「平台当初返回的就是这个」——后者靠作品可信度与抓取日志。

## D17 `cargo deny` 的许可证白名单按依赖树放开，advisory 只放行 unmaintained

**背景**：把 `cargo deny check` 接进 `just check` 与 CI 时，它红了 14 条：12 条是许可证
（`Zlib` / `ISC` / `BSD-3-Clause` / `BSL-1.0` / `CDLA-Permissive-2.0`，来自 `ring`、`slotmap`、
`konst`、`webpki-roots` 等纯传递依赖），2 条是 `unmaintained` 公告（`paste`、`proc-macro-error2`）。
**决定**：五条许可证全部加进 `allow`；两条 advisory 按 ID 加进 `ignore` 并写明来源与影响面。
**边界**：只放行 unmaintained，`vulnerability` 与 `unsound` 一律不放行，出问题必须真修。
**为什么值**：这五条都是 OSI 认可的自由许可证，且没有一条是本项目直接选的——卡住它们等于
卡住 `ureq`/`leptos` 的整条依赖链；而 `paste` 与 `proc-macro-error2` 只在宏展开期跑，
运行时不进二进制，等 leptos 换代自然消失。
**复核**：`just deny`，应输出 `advisories ok, bans ok, licenses ok, sources ok`。

## D16 报告与证明、证据用同一选择口径

**背景**：报告最初是手工对着 `proofs.json` 跑 `report-one` 生成的 100 份文件。
立刻出现两个问题：重跑要手敲 100 次；并且没有任何机制保证覆盖的是同一批数据集。
**决定**：新增 `reports` 子命令，筛选条件照抄 `proof::prove_top`
（`has_preview == 1` + 按 `score` 降序 + `truncate(top)`），文件名统一走 `util::safe_id`。
前端是否显示下载链接不靠 `proof.is_some()` 猜，而是由 `export` 落一个 `report` 布尔字段——
证明和报告将来谁先跑、谁多覆盖一条，链接都不会指到 404。
**代价**：`export` 多读一次报告目录（每行一次 `is_file`）。
**为什么值**：三份产物（证明、证据、报告）覆盖同一批数据集，页面上「已证 / 有报告 / 有证据」
三枚徽章不会互相矛盾；重生成一条命令即可，还能拿 `git diff` 确认没漂。

## D12 全量重写为 Rust 工作区，前端上 WASM

**背景**：原型是 Rust 采集 + Python 聚合 + 原生 JS 前端。三套语言、四处口径，
改一个分类要同步三个文件，出过「Python 的 score 覆盖了 import」这种事故。
**决定**：一个 workspace 三个 crate（`core` / `cli` / `web`）。Python 只保留在历史分支，
仓库内不再有 Python 运行时依赖；前端改成 Leptos 0.7 CSR + trunk 打包成 WASM。
**代价**：前端从「改 HTML 就见效」变成要等编译；WASM 产物体积 460KB。
**为什么值**：口径只有一处实现（`scoring.rs`），类型把字段钉死；前端也在 clippy 门禁内。
**验证**：重算 `summary.json`，标量与 2,500 个部门与旧产物完全一致；100 条定理哈希与顺序一致。

## D13 重构期间用「口径对齐」当验收，不靠肉眼

**背景**：重写最容易出的事故不是编译不过，而是数字悄悄变了——少算一天、四舍五入差一位、
累加顺序不同，报告看起来正常但结论漂了。
**决定**：拿冻结的 `out-full/items.jsonl` 重算，逐字段对比旧 `summary.json`；证明对比哈希；
导出对比前 200 条的关键字段。差异必须解释清楚才能继续。
**代价**：每次改统计都要多跑一轮对比。
**为什么值**：这次真的抓出三处偏差——时间戳 `09:70:21` 被 Rust 接受但 Python 拒绝、
浮点缩放导致 `0.15535` 从「略小于半值」变成「恰好半值」、滞后天数少算一天。
**边界**：对齐只保证「和旧版一致」，不保证旧版就是对的；口径本身要改时另说。

## D14 舍入用格式化，不用缩放取整

**背景**：`(x * 10000).round() / 10000` 看着等价于 `round(x, 4)`，但乘法会引入新的误差。
实测 `0.15535 * 10000 = 1553.4999999999998`，再套一层「半值取偶」就变成 1553，
而真实值略小于半值，本该也是 1553——可换个数字就翻车。
**决定**：`round_to` 走 `format!("{:.n}")` 再解析回来。Rust 的定点格式化与 Python 的
`round()` 同口径（最近舍入、半值取偶）。
**代价**：每次舍入有一次字符串分配；聚合 2.4 万条无感（0.19 秒）。
**为什么值**：报告里的数字必须能对上，一位之差就会让人怀疑全部结论。

## D15 前端也在门禁内：clippy-wasm 与 `-D warnings`

**背景**：前端容易变成「能跑就行」的盲区，死代码和没接上的字段会一直躺着。
**决定**：`just clippy-wasm` 与 `just check` 同级；`-D warnings`。
并且优先「把字段用起来」（证据文件做下载链接、证明显示序号与来源），而不是 `#[allow(dead_code)]`。
**代价**：改 UI 时编译门槛更高。
**为什么值**：字段没用上通常意味着功能漏了——这次就是靠它补出了「字段对不上的地方」面板
和证据包下载链接。

## D1 不做后端，静态 JSON + 静态页

**背景**：5 天赛制，一个人写前后端会死在部署上。
**决定**：Rust 定时跑出 `web/data.json`，前端纯静态读取。
**代价**：不能实时查询；筛选只能在前端做。
**为什么值**：断网可演示，部署成本为零。

## D2 指标对齐 GB/T 36344-2018，不自创维度

**背景**：第一版自拟了五个维度，讲得通但没有权威背书。
**决定**：用国标六维（规范性、完整性、准确性、一致性、时效性、可访问性）做映射，只实现能自动计算的五维。
**代价**：要解释「为什么少一个」。
**为什么值**：被问「你的评分依据是什么」时有答案，而不是「我们觉得」。

## D3 明确不评价准确性

**背景**：准确性需要权威数据源比对，平台不提供。
**决定**：报告里写「不评价」，并给出接入权威源的路线。
**为什么值**：说清边界比给一个假装精确的分数可信。

## D4 Lean 只证算术，不证「数据是真的」

**决定**：定理只覆盖「从这份快照推出的计数/比率/阈值判断」。
**边界**：快照用 SHA-256 钉住时点；平台数据真伪不在证明范围。
**讲稿口径**：「证明的是我们的推导，不是平台的数据。」

## D5 字段一致性分三类，而不是「缺失/多出」

**背景**：第一版把「声明名带部门前缀」算成缺失，1,251 条被高估。
**决定**：分 `列数不一致` / `字段集合不一致` / `仅命名不一致`，只有前两类算问题。
**代价**：多一层判断逻辑。
**为什么值**：误判会让整个报告的信任度归零，宁可细分。

## D6 CI 永远不访问政府网站

**决定**：CI 只跑 `fixtures/snapshot.json`（脱敏 3 行样例）与黄金文件。
**为什么**：外部接口不稳定、有爬取频率问题、快照不可复现。

## D7 原型阶段允许 Rust 里重复 `post/enc`

**背景**：`assay-core` 与 `full_audit` 各有一份 HTTP 封装。
**决定**：先不抽 lib，等前端跑通再重构。
**代价**：改一处要改两处。
**触发条件**：出现第三次改动时立刻抽 `lib::http`。

## D8 Rust 而不是 Python 做主干（已被 D12 取代）

> 当时的决定是「Rust 采集 + Python 聚合」。D12 之后 Python 全部移除，保留此条仅作演进记录。

**决定**：采集、规则、证明生成、内核调用都在一个 Rust 二进制里。
**为什么**：现场无运行时依赖；8 线程原生并发；「基础设施」赛道的故事更硬。
**Python 的位置**：只做一次性聚合与导出，不进交付主链路。

## D11 解释层带数字护栏，不合格就不展示

**动机**：赛道是 AI × 数据，产品里必须真的用到模型；但实测已经证明它会在空文档上编数字，
所以模型只能出现在「解释」这一步，且输出必须被机械核对。
**做法**：模型拿到的是一份事实字典；输出里出现的每个数字都要在事实里出现（比例同时接受小数与百分数写法），
全文最多引用 3 个数字；空输出、被截断、数字越界都算不合格——重写一次，仍不合格就标记 rejected，页面上不展示。
**验证**：`scripts/test_guard.py` 6 个用例进 CI；100 条真实数据 100/100 通过。
**边界**：护栏只管数字，不管语义。措辞歪曲仍需人看。

## D10 存证不用 LLM 抓页面，只落盘接口原始响应

**背景**：原计划用 DeepSeek `read_url` 抓平台详情页，作为「第三方渲染视角」的存证。
**实测**：详情页是客户端渲染，`web_fetch_tool_result` 里的 `source.data` 长度为 **0**，
只有 title「浙江数据开放」和一个 published_at。但模型在 thinking 里仍「原样抄出」了
「数据条数：382」这类页面上不存在的数字。
**决定**：存证只走确定性抓取（catalogDetail + catalogDataPreview 原始字节 → SHA-256），
模型不参与任何取数环节。
**结论**：空文档 + 模型补全 = 伪造证据。这条必须写进讲稿，它比任何「我们用了 AI」都有说服力。

## D9 证明门禁抄 `yamafaktory/formal`

**决定**：拒绝 `sorry`/`admit`；内核 PASS 才写接受标记；失败不缓存。
**为什么**：证明里出现 `sorry` 等于没证明，而多数 demo 会忽略这一点。
