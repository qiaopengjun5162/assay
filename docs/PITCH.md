> 所有数字来自 2026-11-14 的一次全量抓取（24,322 个数据集，0 条详情失败）。
> 讲的时候必须带上这个日期——数据会漂移，说清时点本身就是可信的一部分。

## 一句话定位

**给公共数据做体检，并让每一条数值结论都能被机器复核。**

不说「数据要素市场」「重塑可信流通」这类大词。评委听完应该记住的是：
「他们真跑了 24,322 个数据集，而且数字能被 Lean 验。」

## 2:40–3:40　篡改演示（这是全场最硬的一分钟）

切终端，敲：

```bash
just tamper
```

真实输出（已实测）：

```
篡改: 0 号数据集第 0 列，空值数 0 → 1
error: Tactic `decide` proved that the proposition
  countEmpty rows_0 0 = 1
is false
内核拒绝（预期）—— 退出码 1
```

> 我只改了一个数字。0 改成 1，内核立刻说这条命题是假的。
> 所以我们没法在报告里编一个数——除非有人重新生成整份证明，而证明里钉着快照的哈希。

## 3:40–4:40　为什么这套东西可信（讲两条链）

```
接口原始响应 ──SHA-256──> 钉住时点
      │
      └──规则计算──> 定理 ──Lean 内核──> PASS
```

> 两条链都没让模型参与取数。
> 我们本来想用大模型去读平台页面做第二路存证，实测发现：**页面返回的文档是 0 字节，模型仍然「抄」出了一个不存在的数字：数据条数 382。**
> 所以我们把 AI 的位置摆在解释层——写人话、做摘要，但**不准算数**。

## 附一：五个必被问到的问题

**Q1「5 行样例能代表 2.26 亿行吗？」**
不能，我们也没这么说。报告里写的是「样例级体检」。样例的作用是暴露**元数据与数据不一致**——比如声明 7 列实际 92 列，看 5 行就够了。要评分布，得接全量导出，那是下一阶段的接口工作。

**Q2「Lean 证明是不是噱头？」**
它证明的是「从这份快照推出的计数是对的」，不是「平台数据是真的」。这个边界我们写在证明页上。它的价值在于：报告被转发十次之后，receipt 仍然能验，不需要信任发布者。

**Q3「和 Great Expectations / Soda 有什么区别？」**
它们是给内部数据管道用的，产出是 dashboard，信任对象是自己人。我们产出的是**对外可交付的审计包**：原始响应 + 哈希 + 定理 + 内核校验。买方不需要装我们的系统。

**Q4「准确性不评价，那体检还有什么用？」**
规范性/完整性/一致性/时效性都能自动算，而且这几项恰好是上架审核最常卡的地方。准确性要接权威源，是路线图不是现状。

**Q5「商业模式？」**
不假设。先证明「有人愿意为一份可验证的体检报告付钱」——最可能是交易所的上架审核环节。原型期不做定价。
