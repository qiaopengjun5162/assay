# 需求说明（REQUIREMENTS）

> 面向：接手的开发者 / AI、评审、以及三个月后的自己。
> 目标不是把功能列全，而是把「什么算做对了」写死，避免后面靠感觉改。

## 1. 问题

政府开放数据平台公布了海量数据集，但「公布」不等于「可用」：

- 页面声明 9 个字段，实际下发 8 列；
- 声明「每年更新」，但数据两年没动；
- 字段说明只有一个字，或者整列全空；
- 想核对，平台的预览接口只给 5 行，人工抽查覆盖不了 24,322 个数据集。

同时，用大模型去「读页面、写结论」不可靠：实测 DeepSeek 的 `read_url` 对该平台返回
**0 字节**文档，模型仍然「抄」出了不存在的「数据条数：382」。

所以需求不是「用 AI 分析数据」，而是：**用确定性方法取数与判定，用机器可验证的方式表达结论，
模型只在最后一步写人话，且它说的话要能被机械检查。**

## 2. 用户与场景

| 用户 | 场景 | 需要的东西 |
|---|---|---|
| 数据交易所 / 上架审核 | 判断一个数据集能不能上架 | 单数据集体检报告 + 可追溯证据 |
| 数据提供方 | 自证合规、定位问题 | 部门维度榜单、问题清单 |
| 企业内部数据团队 | 选外部数据源 | 榜单排序、字段一致性、时效性 |
| 评委 / 第三方 | 验证结论是否可信 | 原始响应哈希 + 可跑的证明文件 |

## 3. 范围

### 3.1 做

- 全量枚举一个省级开放平台的数据集目录（当前：浙江，24,322 个）
- 逐条抓字段定义与样例（表头 + 最多 10 行）
- 计算五类可自动判定的指标（见第 4 节）
- 输出榜单、单数据集报告、部门维度聚合
- 对问题最多的前 500 名：原始响应存证 + Lean 4 定理证明（D23）
- 生成静态站点，前端可离线演示

### 3.2 不做（非目标）

| 不做 | 原因 |
|---|---|
| 评价数据「准确性」 | 没有权威源可比；评了就是编 |
| 处理全量 2.26 亿行记录 | 样例级体检，接口只给 5 行 |
| 账号体系 / 后端服务 / 数据库 | 静态站即可满足演示与交付；零运维 |
| 现场依赖外网 API | 比赛现场网络不可控，前端与证明均静态 |
| 自动抓取需要登录的数据 | 只做公开、免登录接口 |
| 让模型参与取数或算数 | 已实测会编数字 |

## 4. 指标定义（可复核的口径）

对齐 **GB/T 36344-2018** 的六维，只实现可自动计算的部分。

### 4.1 字段一致性（一致性）

设声明字段集合 `D`，样例表头集合 `S`：

| 分类 | 判定 | 是否计入 schemaMismatch |
|---|---|---|
| 一致 | `D == S` | 否 |
| 列数不一致 | `|D| != |S|` | 是 |
| 字段集合不一致 | `|D| == |S|`，存在非前缀关系的差异 | 是 |
| 仅命名不一致 | `|D| == |S|`，`D` 中每个名字都是 `S` 中某个名字加前缀 | 否（单列统计） |
| 无样例 | `S` 为空 | 否（单列统计） |

> 注意：`summary.schemaMismatch` 沿用历史口径，统计「对不上」的三类之和（含仅命名不一致），
> 用来发现命名差异；判断结构性问题请只看 `mismatchKinds` 里的分类。

前缀判定：`d.ends_with(s) || s.ends_with(d)`。

**为什么单列「仅命名不一致」**：第一版把它算成字段缺失，导致 1,251 条虚高；
抽查「洞头区文旅体行业民宿信息（鹿西乡）」发现声明 13 列、样例 13 列，
只是声明名多了「鹿西乡民宿」前缀。这是命名习惯，不是数据问题。

### 4.2 完整性（样例级）

- 空值判定：单元格为 `null`、空串、或去除首尾空白后为空 → 空值
- 空值率 = 空值单元格数 / (行数 × 列数)，保留 4 位小数
- 整列全空：某列空值数 == 行数
- 样例行数来自预览接口（通常 5 行，最多 10 行）

### 4.3 时效性

- 基准日：**2026-11-14**（常量 `NOW_YMD`，不取系统时间，保证可复现）
- 滞后天数 = 基准日 00:00 − `updateTime`，按天向下取整；负数记 0
- 声称逾期：声明周期与阈值对照

| 声明周期 | 阈值（天） |
|---|---|
| 1（每日） | 7 |
| 7（每周） | 10 |
| 30（每月） | 45 |
| 365 / 每年 | 400 |

- 停更标记：`updateCycle ∈ {-1, 999, 不更新}`

### 4.4 规范性

- 字段说明字符数 < 10 → 计入 `noDescription`
- 声明列数为 0 → 计入 `noColumnList`

### 4.5 可访问性

- `hasPreviewData == 1` 且预览接口返回表头 → 视为可预览
- 无样例单独计数

### 4.6 问题分（仅用于排序）

```
score = 3 × [列数不一致 或 字段集合不一致]
      + 1 × [仅命名不一致]
      + 2 × [存在整列全空]
      + min(3, 空值率 × 6)
      + 1 × [停更]
      + 1 × [字段说明 < 10 字]
      + 1 × [无样例]
```

保留 2 位小数，半值取偶（与 Python `round` 同口径）。
**这不是质量评分**，只是把「值得先看」的排前面；权重公开在 `crates/core/src/scoring.rs`。

| 编号 | 需求 | 验收 |

| R1 | 全量枚举目录 | 返回 24,322 条，8 线程 < 60 秒，0 页缺失 |

## 6. 验收标准（Definition of Done）

一个改动只有同时满足以下条件才算完成：

1. `just check` 全绿：`fmt --check`、`clippy -D warnings`、全部单测、证明门禁
2. `just clippy-wasm` 全绿（前端也在门禁内）
3. `cargo test` 覆盖新增逻辑；纯函数必须有单测
4. 若改动影响口径（分类、评分、聚合、导出），必须跑 **口径对齐检查**：
   用 `out-full/items.jsonl` 重算，`summary.json` 与冻结快照逐字段一致，
   或明确记录「为什么允许变化」
5. 若改动影响证明，`just prove` 必须 PASS，且 `proofs.json` 的哈希与顺序可解释
6. 文档同步：`README` / `docs/ARCHITECTURE.md` / `docs/DECISIONS.md` 至少一处更新
7. 不引入新的 Python 运行时依赖

## 7. 约束

- **比赛现场**：不依赖外网；前端与证明静态可跑；`cargo build --offline` 需提前 vendor
- **可复现**：所有引用数字对应 2026-11-14 快照；基准日写死在代码里
- **安全**：任何 key 不得进仓库、日志、issue；`.env` 与本地配置不入库
- **依赖**：crates.io 在部分网络下 403，CI 正常，本地需代理或 vendor

## 8. 已知边界

- 样例只有 5 行，完整性结论是**样例级**，不能外推成全量质量
- 平台接口是事实标准（`/dopServer/...`），非官方承诺 API，字段可能变
- 证明证的是「从这份快照推出的计数」，不证平台数据本身的真实性
- 数字护栏只管数字，不管语义；措辞歪曲仍需人看
